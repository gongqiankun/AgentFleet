# AgentFleets for Codex · zero-dependency multi-platform distribution

The release builder first produces a Node 24 Single Executable Application
(SEA). The local agent is bundled into one CommonJS entry with `esbuild`, a SEA
blob is generated by Node 24, and `postject` injects it into a copy of the exact
Node executable. The finished artifact is smoke-tested with `--version`.

```sh
./packaging/build-release.sh 0.5.0
```

If SEA construction fails on the build host, `build-release.sh` falls back to a
tarball containing the compiled ESM agent and its private Node 24 runtime. Both
formats give the target user the same `agentfleet` executable entry point and
require no system Node or npm installation.

The production build publishes Linux x86_64, macOS x86_64/arm64 and Windows x86_64 artifacts with one `release/manifest.json`, plus platform Codex artifacts in `codex-manifest.json`. Publish them without renaming at:

```text
GET /downloads/manifest.json
GET /downloads/<manifest.artifacts.linux-x64.file>
GET /install                         (the exact packaging/install.sh content)
GET /install-macos                  (macOS installer)
GET /install.ps1                    (Windows PowerShell installer)
```

A version is immutable: both builders refuse to replace an existing artifact
or checksum for that version, including switching the format between SEA and
portable. Release builds are serialized within one output directory. Use a new
semantic version for every changed binary.

A release version is immutable across both formats. If either the SEA or
portable artifact (or its adjacent checksum) already exists for a version, the
builders exit with status 73 before compiling or changing `manifest.json`.
`build-release.sh` will not disguise that collision by falling back to the
other format. Bump the package version for every content change; never delete
and republish a released version. Publication stages and validates the full
artifact/checksum/manifest tuple, then uses same-filesystem hard links to make
versioned files visible without overwrite, so the release output filesystem
must support hard links.

The dependency-free installer derives the download origin from its required
`--url`, permits HTTPS (plus loopback HTTP for development), validates all
manifest fields, checks artifact size, verifies SHA-256 before execution, and atomically switches
`~/.local/bin/agentfleet`. The prior symlink is retained as
`~/.local/bin/agentfleet.previous` for rollback. It then forwards the original
arguments to `agentfleet onboard`.

Example browser-generated command:

```sh
curl -fsSL https://fleet.example.com/install | sh -s -- \
  --url https://fleet.example.com \
  --ticket '<enrollment-id>.<bootstrap-secret>' \
  --name "$(hostname)"
```

The ticket is sent only in the Agent HTTP claim body. It is never added to a
URL, service unit, manifest, or agent log. The bootstrap API contract is:

```text
POST /api/agent/enrollments/claim
  { ticket, publicKey, name, platform, platformRelease, architecture, agentVersion }
  -> { enrollmentId, claimToken, proofMessage, publicKeyFingerprint,
       verificationPhrase, expiresAt, recoveryWindowSeconds }

POST /api/agent/enrollments/exchange
  { enrollmentId, claimToken, signature }
  -> guided install: immediately redeems the browser-preauthorized enrollment
  -> legacy manual pairing: 409 ENROLLMENT_NOT_CONFIRMED until browser confirmation
  -> { machineId, workspaceId?, agentToken, credentialExpiresAt? }
```

The service stores only its data directory in `ExecStart`; it reads the paired
origin and credential from the mode-0600 local SQLite state. Release lifecycle
operations put their mode first:

```sh
# Download, verify, atomically activate, and restart an existing service.
curl -fsSL https://fleet.example.com/install | sh -s -- \
  --update-only --url https://fleet.example.com

# Atomically swap the current/previous version and restart it.
curl -fsSL https://fleet.example.com/install | sh -s -- --rollback

# Stop the background service and remove managed launchers/binaries; preserve state.
curl -fsSL https://fleet.example.com/install | sh -s -- --uninstall

# Also remove the default local AgentFleet identity and connection state.
# Codex sessions and project files are never removed.
curl -fsSL https://fleet.example.com/install | sh -s -- --uninstall --purge
```

An update that cannot restart restores the prior launcher and service unit. A
managed-directory marker, strict version-directory paths, regular-file/link
checks, a per-version artifact digest pin, an installer lifecycle lock, and
archive traversal/type validation bound all destructive operations.
Run `packaging/install.sh --self-test` for the dependency-free parser/path
smoke checks. Root uses a system service and fixed root-owned install paths;
non-root accounts use a user service. User lingering is inspected, never enabled
automatically.

Every installed version also contains a mode-0600 `.artifact-metadata` record
pinning the manifest filename, format, size, and artifact SHA-256. Reusing a
version succeeds only when that complete record matches; a missing, linked, or
different record fails closed. SEA bytes are rehashed before the installer
executes the existing binary. For portable installs, the record pins the
verified source archive even when its launcher is unchanged.

Release builds and installer lifecycle changes are serialized by private lock
directories. An uncatchable process termination can leave a stale
`.agentfleet-release-build.lock` or `.installer-lock`; first confirm that no
builder/installer is running, then remove only that specific empty lock
directory. Run the regression suite as a non-root user and the root smoke in an
isolated container:

```sh
docker run --rm --user node -v "$PWD:/repo:ro" -w /repo node:24-bookworm \
  sh packaging/test-immutability.sh

docker run --rm -v "$PWD:/workspace" -w /workspace node:24-bookworm \
  .github/scripts/smoke-install.sh
```
